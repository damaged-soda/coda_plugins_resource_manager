## 一期留下的小问题

| 问题 | 建议 |
|---|---|
| `coda.watch` 失败时静默，只剩手动刷新 | 作者定先不做，真实发生了再说 |
| 目录每取一页都重读并排序 | 看实测，卡了再加缓存 |
| 恢复时某页取失败，重试能取够条数，但滚动位置已用掉，回不到原处（二期评审 P2） | 很少发生，点几下能回去，先不修 |
| 恢复途中关闭页面，还没用上的已加载条数不会保存（二期评审） | 同上 |
| 启动超时只看首个 `root`；之后切会话如果等不到 `root`，不再有提示（二期评审） | 真实发生了再说 |
| 文件页首次读取失败时，待恢复的阅读位置被用掉，重试成功后回到开头（PR #2 评审 P2） | 很少发生，影响小，先不修 |
| 恢复上限约 2 万条，超过的回来后要再点「再显示」 | 已接受 |
| Mac 右键菜单有「在新窗口打开帧框」，点了没反应 | 客户端的问题，已提 #2140，插件不绕开（作者定） |
| iPhone 文件页的系统返回可能直接回到会话，不回目录树（作者实测时的感觉，二期测时是能回到目录树的）；页面内按钮解决不了 | 作者定保持现状。可能是客户端两条导航路径混用，未验证。真要改，就是像 Mac 一样在页内切到文件，或等上游 |

## 设计时要注意的约束

| 约束 | 来源 | 对本插件的影响 |
|---|---|---|
| iPad 分栏下，推入非会话页可能把列表选中清空，导致跳转失败 | #1344 | 作者决定不单独验证 iPad，风险记在这里 |
| 过期响应不能覆盖用户后来的选择 | #150 | 目录和文件读取都要丢弃迟到的回答 |
| 工作树可能存到自定义位置或外置盘 | #1002 | 只用 `checkout.path`，不假设路径规律 |
