# 资源管理器：一期设计

状态：设计评审已通过（Codex gpt-6.1-sol high，一轮加两次复审）。标「作者定」的是已拍板的，其余是主会话的方案。

## 1. 目标

让用户在 Mac 的会话侧栏里，不离开对话就能看到这个会话的工作目录：浏览目录、读文本和图片、把路径交给对话。

衡量标准：

- 在 320 点宽的侧栏里，能打开一个有上万文件的仓库，展开目录和打开文件都不卡住界面，也不拖慢其他插件。
- Agent 一轮改完文件后，已展开的目录和正在看的文件不用手动操作就更新。
- 切换会话时，树和预览都换成新会话的，不会显示上一个会话的内容。
- 路径校验拒绝任何读到工作目录之外的请求。

## 2. 已定事项

- 资源管理器是会话工作目录的文件浏览器（作者定）。
- 一期只读，只限会话工作目录（作者定）。
- 先做 Mac，iOS 放二期；iPad 和 Duo 不单独设计和验证，并入 iPhone 的设计（作者定）。
- 以外部插件方式开发，同时在 coda-console/coda#1756 沟通接口；该 issue 上游未开工（作者定，作者已和 Coda 开发者确认）。
- 目录树和预览拆成两个模块，上游的预览落地时可以替换预览（作者定）。
- 目录和文件都用请求和回答传输，不用集合（作者定，见第 6 节）。
- 预览放在侧栏内，独立窗口放二期（作者定）。
- 路径只通过复制和拖动交给对话；写草稿不是公开契约，先在 #1810 下询问（作者定）。
- 默认只隐藏 `.git`、`.DS_Store`（作者定）。
- 预览上限：文本 1 MiB、图片 8 MiB（作者定）。
- 零依赖 `.mjs`，无构建步骤；文档中文，标识符英文。

## 3. Spike 实测

2026-11-04 在作者的 Mac 和 iPhone 上跑过一次性 spike（不进本仓库）。两台设备都连同一台后端。**没有测过经 SSH 或远程空间的连接。**

| 项目 | Mac | iPhone |

| 页面尺寸 | 侧栏 320×789 | 420×790 |
| 消息往返 p50 | 14～39 ms | 41～81 ms |
| 一问一答取块 | 1.1～3.1 MiB/s | 0.7～1.8 MiB/s |
| 模块连发 | 3.8～4.3 MiB/s | 2.8～4.9 MiB/s |
| 64 KiB 和 90 KiB 的块 | 没有明显差别 | 没有明显差别 |
| `blob:` 图片 | 可显示 | 可显示 |
| `coda.open('file:///…')` | 报「打不开」 | 报「打不开」 |
| `coda.open({ view })` | 开独立窗口（1100×720），侧栏不卸载 | 推入一层，**侧栏视图随即卸载，返回时重新打开** |
| 拖到输入框 | `dropEffect: copy`，作者确认符合预期 | 未测 |
| 模块写草稿 | 版本号递增、无冲突，作者确认符合预期 | 同左 |

其他实测：

- `coda.api('threads/<id>')` 返回 `checkout`，`kind` 见过 `worktree` 和 `original`。
- `coda.watch('threads')` 能看到一轮开始和结束（`turn` 由 ID 变 `null`）。
- `onContext` 能收到换会话。
- 被别的视图打开时，`view.context.session` 是 `null`，所以要把会话 ID 放进 `args`。

这些速度只作参考，不是保证。

## 4. 数据链路

| 量 | 入口 | 经过 | 消费方 | 核实 |
|---|---|---|---|---|
| 会话 ID | 客户端打开侧栏、换会话 | `view.context.session`、`onContext` → 模块推 `session` | 页面 `model` | 实测；客户端不会直接告诉页面换了会话（评审核实） |
| 根目录 | `GET threads/<id>` 的 `checkout.path`、`state` | `root` → 模块推 `root` | `paths`、页面 | 实测；这个返回结构不是文档写明的契约，只在 `root` 一处读取。`threads` 集合只有 `{ id, turn }`，根目录状态变化要模块自己重新查询 |
| 展开状态 | 用户操作 | 页面 `model`；`setState` / `getState` | 页面发 `list` | `setState` 按视图加 `args` 隔离，没有会话维度（评审核实） |
| 目录内容 | `fs.readdir` | `tree` → `listed` | 页面 `model` | 消息实测 |
| 文件块 | `fs.read` | `content` → base64 → `chunk` | 页面预览 | 实测 |
| 刷新信号 | `coda.watch('threads')` 的一轮结束 | 模块推 `changed` | 页面重新请求 | 实测 |
| 路径交接 | 用户操作 | `coda.copy`、HTML 拖动 | 剪贴板、输入框 | 实测 |

## 5. 结构

```text
package.json          id: resource-manager，side 视图，分类「工作流程」
main.mjs              注册视图，跟踪会话和代次，把请求路由到下面的模块
lib/root.mjs          从会话取根目录，唯一读取 checkout 的地方
lib/paths.mjs         路径校验
lib/tree.mjs          读目录、排序、分页
lib/content.mjs       分块读文件、判断类型
view/index.html
view/protocol.mjs     消息格式和上限，页面和模块共用
view/app.mjs          页面入口和消息收发
view/model.mjs        纯状态：树、选中、代次与过期判断、状态裁剪
view/tree.mjs         渲染目录树
view/preview.mjs      渲染预览，可独立替换
view/style.css
test/*.test.mjs       node --test
```

依赖方向：`main` → `lib/*`；`view/app` → `model`、`tree`、`preview`。模块和页面只通过消息通信，两边都只依赖 `view/protocol.mjs`。

展开状态只有页面一份。模块只记当前会话、代次和根目录，不记展开了什么。

## 6. 模块

### 消息协议

所有消息都带 `generation`（代次）。模块每次换会话就加 1。

| 方向 | 消息 | 内容 |
|---|---|---|
| 页面 → 模块 | `hello` | 页面就绪。模块回当前的 `session` 和 `root` |
| 模块 → 页面 | `session` | `generation`、`session`。收到后立即清空树、预览和未完成的请求 |
| 模块 → 页面 | `root` | `generation`、`state`（`ready`、`none`、`preparing`、`gone`）、`path` |
| 模块 → 页面 | `changed` | `generation`。这个会话一轮结束了 |
| 页面 → 模块 | `refresh` | `generation`。用户手动刷新，模块先重新查询根目录 |
| 页面 → 模块 | `list` | `generation`、`requestId`、`path`、`cursor` |
| 模块 → 页面 | `listed` | `generation`、`requestId`、`entries`、`nextCursor`，或 `error` |
| 页面 → 模块 | `read` | `generation`、`requestId`、`path`、`offset` |
| 模块 → 页面 | `chunk` | `generation`、`requestId`、`data`、`offset`、`size`、`mtimeMs`、`kind`、`eof`，或 `error` |

规则：

- **过期判断**：模块只回答当前代次的请求，异步读完后再核对一次。页面丢弃不是当前代次、或不是这条路径最新请求的回答。A→B→A 时第一次 A 的迟到回答因代次不同被丢弃。
- **每个请求都有回答**：失败也回 `error`（`code`、`message`）。页面设 30 秒超时，超时显示原因和重试。
- **启动**：`hello` 同时承担宿主重启后的恢复。视图被客户端重新打开时页面整个重载，重新走一遍 `hello`。

### 根目录

- 没有会话、`state` 不是 `ready`、目录已不存在（worktree 归档后会被回收）都是正常状态，页面各显示一句说明。
- 只用 `checkout.path`，不假设路径规律（工作树可能在别的盘，见 #1002）。
- 根目录的真实路径和代次一起记录。

**根目录状态会变**：新会话的工作树还在准备时就可能打开侧栏，归档后工作树会被回收，再发消息又会重建。模块在这些时候重新查询（作者定）：

- 这个会话一轮开始和结束时；
- 收到 `refresh` 时；
- 状态是 `preparing` 时每 2 秒一次，变成其他状态或视图关闭就停。没有确认「一轮开始」一定晚于工作树就绪，所以不只靠一轮开始。

查询结果和上次不同才推 `root`，异步返回后核对代次。

页面收到 `root` 时不清空界面，只在 `session` 时清空：

- 变成 `ready`：请求根目录并恢复已保存的展开状态。
- 从 `ready` 变成其他状态：树和预览显示对应说明，展开状态保留，下次 `ready` 时恢复。

### 路径校验

- 页面只传相对路径。拒绝绝对路径、`..` 片段和控制字符。
- 用 `realpath` 得到规范路径，判断它等于根目录或以「根目录 + 路径分隔符」开头。不能只比字符串前缀，否则 `/repo-other` 会误匹配 `/repo`。
- `paths` 返回规范路径，读目录和读文件都只用这个返回值。每次读取都校验。
- 符号链接：目标在根目录内就照常处理；目标在外就显示为链接，不能展开或打开。只对符号链接做额外解析，并限制并发。
- 校验后到读取前被替换这类并发情况不处理（P3）。

### 目录

- 只读已展开的目录，不做递归扫描。
- 先目录后文件，按名字不分大小写排序。
- 隐藏规则放在页面：模块回答全部条目，页面按名字过滤，所以切换开关不用重新请求。默认隐藏 `.git`、`.DS_Store`，工具栏开关可显示全部。
- 按序列化后（含 JSON 转义）的 UTF-8 字节数分页，每页不超过 96 KiB，用 `cursor` 取下一页。超大目录显示「再显示」。

**刷新一个目录**：

1. 页面记下这个目录已加载的条目数，按顺序重新取页，直到条数够了或没有下一页。
2. 全部取回后，一次替换这个目录的内容，所以不会出现重复或漏项。
3. 同一目录有新刷新时，旧的结果作废。
4. 回答 `not_found` 的目录，从树和展开状态里移除。

### 文件内容

- 页面按偏移请求块，一问一答，每块原始 64 KiB，用 base64 编码（约 87,384 字符），加上消息包装后不超过 128 KiB。
- 回答不回传路径，避免长路径占用消息大小；页面用 `requestId` 对应。
- 文本把所有块的字节拼起来后再用 `TextDecoder` 解码，避免多字节字符被切开。
- 用前 8000 字节是否含 NUL 判断二进制（同 Coda 的 `worktree-changes`）。
- 文本最多读 1 MiB，超过的显示前 1 MiB 并说明。
- 图片支持 PNG、JPEG、GIF、WebP、SVG，上限 8 MiB，用 `blob:` 经 `<img>` 显示，带进度。
- 其他文件只显示大小、修改时间和复制路径。

### 刷新

- 触发：这个会话一轮结束（模块推 `changed`）、工具栏刷新按钮（发 `refresh`）、页面重新打开。根目录先按第 6 节更新。
- 一期不用 `fs.watch`，放到二期。
- 页面按上面的规则重新取全部已展开目录，并行不超过 8 个。
- 正在预览的文件也重新请求第一块；`size` 或 `mtimeMs` 变了就重读。回答 `not_found` 时说明文件已不存在。

### 性能约束

宿主是所有插件共用的进程：只用异步 IO，不用同步 fs，不做全量扫描，单次操作有上限。重读目录的代价要在验收时用真实规模观察，不靠推论。

## 7. 页面

- **树**：扁平行列表，缩进表示层级，按 `--coda-*` 变量取色，字号跟 `--coda-font-size`。要能在 320 点宽下使用。
- **预览**：在侧栏内进入下一层，`toolbar` 给返回按钮。
- **文本**：一个 `<pre>` 放正文，另一个放行号，不换行，横向滚动。这样跨行选中和复制不会带上行号。
- **路径交接**：右键菜单复制相对路径或绝对路径；行可拖动，拖出的是相对路径的 `text/plain`。
- **工具栏**：刷新、显示隐藏文件、预览时返回。

**状态保留**：

- 切走标签或收起侧栏时视图会卸载，所以展开目录、选中项和滚动位置要用 `setState` 保存。
- `setState` 没有会话维度，所以状态内部按会话分开。状态只在 App 运行期间保留。
- 按序列化大小裁剪，总量不超过 96 KiB：先淘汰最旧的会话，再裁当前会话过多的展开目录。只存界面状态，不存目录内容、正文或图片。
- 交互后及时保存；`visibility: false` 只作最后补存，不依赖它。
- 恢复时重新请求已保存的展开目录，不存在的直接丢弃。

## 8. 二期会受影响的点

iOS 上打开文件要推入新视图，树视图会被卸载（第 3 节实测）。一期可复用的只有路径校验、内容读取、消息协议、预览渲染和状态模型。

二期要另做：

- 文件视图的入口：从 `args` 取会话和路径，独立初始化，它有自己的模块实例和状态。
- 后续参数更新要处理 `context` 事件，`coda.args` 只是启动值。
- 返回时重建树。
- `toolbar` 只有 Mac 有，iOS 要用页面内控件，并自己处理安全区和横屏返回。

一期要守住的是：`preview.mjs` 不依赖树的状态，只接收「会话 + 路径」。
