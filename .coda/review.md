# 资源管理器评审准则

Coda 插件：会话工作目录的只读文件浏览器。设计在 `docs/design/`，Coda 的插件契约以 coda-console/coda 的 `docs/plugins.md` 为准。

## 分级

| 级别 | 含义 |
|---|---|
| P0 | 需求没达成，或核心功能在正常路径上不可用 |
| P1 | 正常路径必然或高概率触发的缺陷；违反红线；与设计或 Coda 契约不符会导致误用 |
| P2 | 小概率触发：失败恢复、罕见数据、边界值 |
| P3 | 对抗性或深层问题，或架构改进建议 |

- 阻断线 P1：P0、P1 要修改后复审；P2、P3 照列，不阻断。
- 效果达成、只是做法不同，不判 P0，至多 P2，并写明等价依据。
- 每条写：文件与位置、触发条件、后果、建议修法；能复现的写出复现。
- 需要取舍的问题单列「待决策」，不要自行定级为阻断。评审意见都由主会话分析后和作者确定。
- 复审只看上轮阻断项和回归，发现要标明是本轮引入还是之前就有。

## 红线（违反即 P1 起）

- **越界读取**：任何路径能读到会话工作目录之外。
- **写入**：有任何写文件的代码路径（`coda.copy` 除外）。写操作要单独设计后才能做。
- **拖慢宿主**：宿主进程里用同步 fs、全量递归扫描，或没有上限的操作。
- **超限**：消息或集合对象可能超过 128 KiB 而没有处理。
- **串会话**：切换会话后显示或写入上一个会话的内容。
- **越界改动**：改了派单范围之外的文件。
- **测试**：要求的场景没有测试，或测试没有真正断言需求。
- **残留**：留下后台进程、临时文件或调试输出。

## 架构审查

与正确性评审同时做，结尾给结论：优秀 / 可接受 / 需重构。

- 内聚：一个模块只做一件事。
- 耦合：`view/` 和 `lib/` 只通过消息和集合通信；不依赖 Coda 未写入文档的行为，确实要依赖的集中在一处。
- 单一事实来源：路径规则、消息格式、上限各只定义一处。
- 可替换：预览模块不依赖目录树。

## 看得轻的部分

注释措辞、小范围的私有函数拆分、测试的组织形式、文档行文风格（只看事实是否与代码一致）。

## 不做生产级对抗审查

恶意客户端、进程被杀的时序、极端性能一律 P3，不发起修复轮。
